# Issue #3：Stage 3 テスト仕様 — 継続確認のEvent方式への移行とAPIクライアントのGUI依存解消

## 1. Event確認
確認要求登録、ワーカー待機、True継続、False中止、要求ごとのEvent独立性、ダイアログ例外時のFalse解除、終了処理による未回答解除、確定済み応答の不変性を確認する。

## 2. APIクライアント独立性
tkinterとtk_notificationsをimportせず、API処理からダイアログを表示しないことを確認する。エラー情報が呼び出し元へ返ることを確認する。

## 3. APIエラー
サービス生成、動画情報、チャンネル情報、コメントスレッド、返信ページの各エラーをモック化する。既存fetch_status、result_data、取得件数の意味と返却タプル構造を維持する。

## 4. 継続確認統合
Trueで後続取得、Falseで中止、部分取得データの保持、上限到達が複数回発生した場合の動作を確認する。

## 5. スレッド境界・GUI統合
確認ダイアログはメインスレッド、ワーカーはEvent待機、APIクライアントはGUI非操作であることを確認する。モックAPIと実際のTkイベントループを使用する。

## 6. 完了条件
Python 3.8.10環境で、Event確認の正常・異常系とAPIクライアントのGUI非依存性を検証できること。
