# Issue #3／Issue #20 テスト環境・実行仕様

## 1. 基準環境

- Python：3.8.10（本プロジェクトの互換性基準）
- 主テストランナー候補：Python標準ライブラリのunittest
- 補助ランナー：pytest
- GUI：Tkinterを利用可能なWindowsデスクトップ環境
- 外部通信：テストでは実YouTube APIへ接続せず、モックを使用する。

新しいテスト依存を追加する場合は、Issue #20で必要性・Python 3.8.10互換性・導入方法を確認して決定する。

## 2. 現在確認できている既存テスト実行結果

2026-11-22、利用者から次の実行結果が報告されている。

- `python -m unittest discover -v`：50 tests、OK。
- `python -m pytest -v`：50 passed（pytest 8.3.5）。

これは当時存在した既存テストの探索・実行結果である。Issue #3 Stage 1～4の新規テストが作成・実行済みであることを示すものではない。また、ここに記載した結果は利用者報告であり、本書の作成時点で独立に再実行した結果ではない。

## 3. 実行コマンド候補

リポジトリルートから実行する。

```powershell
python -m unittest discover -v
python -m pytest -v
```

unittestの探索には、現在のパッケージ構成とテスト配置に応じた探索起点・パッケージ構造が必要である。テストファイル配置・命名・探索設定の最終決定はIssue #20で行う。

## 4. テスト環境の分離

### GUI不要の単体テスト
- Tkルートを生成せずに実行できる構造・関数はヘッドレスで実行する。
- Thread、Event、Queue、API、ファイル保存をモック化する。
- Thread.start()失敗、ワーカー例外、要求処理例外を再現する。

### GUI統合テスト
- Tkイベントループを実際に動作させられるデスクトップ環境で実行する。
- ダイアログはモック化し、表示内容・呼び出し回数・実行スレッドを検証する。
- APIと保存処理はモック化し、ネットワークや実データに依存させない。
- rootおよび生成したスレッドをテスト終了時に確実に後始末する。

GUI統合テストが実行できない環境では、未実施として記録する。ヘッドレス単体テストの成功で代替合格としない。

## 5. モック方針

- YouTube APIクライアント：正常応答、ページ継続、APIエラー、コメント無効、遅延を制御する。
- Tk通知・ダイアログ：種類、引数、回数、順序、実行スレッドを記録する。
- Thread：start成功・失敗、ワーカー完了・例外を制御する。
- ファイル保存：成功、False戻り値、例外、複数ファイルの部分成功を再現する。
- 時間・待機：可能な限りEvent／Barrier等で同期し、実時間sleepを最小限にする。

## 6. 実行結果の記録

実行ごとに、日時、ブランチ・コミット、Python・ランナーのバージョン、コマンド、検出件数、成功・失敗・スキップ件数、GUI環境の有無、モック条件、失敗概要を記録する。

既存回帰テストとIssue #3新規機能テストの件数・結果を分けて報告する。unittestとpytestの双方で同じテストを実行する場合は、重複したテストケース数を合算しない。

CIの有無・方式、テスト配置、命名規則、GUI統合テストをCIで実行するか、ローカル受け入れ確認にするかは、本書では未確定とする。Issue #20でリポジトリの実行環境と運用制約を確認して決定する。
