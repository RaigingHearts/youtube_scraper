# Issue #3：Stage 4 テスト仕様 — 協調的キャンセルとアプリケーション終了制御

## 1. 終了確認と状態遷移
ワーカー不在時は即時終了。実行中は終了確認を一度だけ表示する。running、confirming、shutdown_pending、stopping、complete、closedの各状態と許可される遷移を確認する。終了確認の重複要求でダイアログや完了処理が重複しないことを確認する。

- キャンセル選択でshutdown_pendingを解除し、判断Eventを設定し、cancel_eventを設定せず通常処理へ戻る。
- はい・いいえでは保存方針を確定してからcancel_eventを設定する。
- 終了確認中もTkイベントループとワーカー監視が継続する。

## 2. 保存判断バリアと競合
終了確認表示前にshutdown_pendingが設定され、ワーカーが保存開始前に判断Eventを待つことを確認する。ロックを保持したままEvent待機しないことを確認する。
- main側が先にpendingを設定した場合、ワーカーが選択確定まで保存を開始しない。
- ワーカーが先に保存開始を確定した場合、終了選択で開始済み保存を中断しない。
- キャンセル選択後は通常保存が可能となり、終了選択後はsave_partial／skip_additional_saveが守られる。
- 保存開始境界で同時に終了要求が発生しても、保存開始とpending設定のどちらか一方に一意に決まる。

## 3. 自然終了との競合
終了確認ダイアログ表示中にワーカーが自然終了するケースを検証する。終了選択を遅れて適用して追加保存しないこと、完了回収を二重実行しないこと、result・exception・保存結果を一度だけ回収してrootを破棄することを確認する。

## 4. キャンセル境界
動画情報、チャンネル情報、コメントスレッド、返信コメントのAPI前後、親コメント・返信ページ処理、ページ間待機、次のAPI開始前、保存開始前でキャンセルを確認する。

## 5. API通信中
通信中の強制中断がないこと、通信終了後に返却済みレスポンスを処理してからキャンセルを検出すること、後続API要求を開始しないこと、取得済みデータを保持することを確認する。cancel_event.wait(0.1)中のキャンセル応答も確認する。

## 6. 保存方針
保存して終了：取得済みデータを既存保存処理で保存し、追加API要求を行わない。ファイル単位の成功・失敗を回収する。
保存せず終了：保存未開始なら追加保存せず、既存ファイルを削除せず、完了済み・開始済み保存を取り消さない。
終了キャンセル：通常処理を継続しcancel_eventを設定しない。
保存失敗・シリアライズ例外時も結果またはexceptionを回収し、終了処理が停止不能にならないことを確認する。

## 7. 部分取得とキャンセル理由
キャンセル後のresult_data保持、既存返却タプル、fetch_status="cancelled"との整合性を確認する。継続確認による中止はcancel_reason="continuation_declined"、アプリ終了はcancel_reason="application_shutdown"となることを確認する。既存のcancel_reasonなしデータとの互換性を確認する。

## 8. 確認要求解除
未回答要求をFalseで解除しEventを必ず設定する。遅延回答で確定済みFalseが上書きされず、回答と終了解除が競合しても一度だけ確定することを確認する。終了中に新しい確認ダイアログを表示しない。

## 9. 終了中の通知
終了中に個別の通知ダイアログを表示せず、通知をFIFOで退避することを確認する。ワーカー終了後、通知内容・種類・順序が一つのサマリーに保持され、警告・エラーが破棄されないこと、通知がない場合にサマリーを表示しないことを確認する。

## 10. ワーカー終了・root破棄
done_event検知、未処理GUI要求回収、result/exception/保存結果回収、GUI後処理、通知サマリー、WorkerHandle解放、root破棄の順序を確認する。ワーカー終了前にrootを破棄せず、非daemonワーカーを正常終了させる。終了待機中もGUIイベントループが動作することを確認する。

## 11. GUI統合
モックAPI・モック保存処理と実際のTkイベントループで、通常終了、保存終了、非保存終了、終了キャンセル、API通信中の終了要求、確認待機中の終了、保存判断バリア、保存開始との競合、自然終了との競合、保存失敗、ワーカー例外、GUIキュー残存、通知集約を検証する。

## 12. 完了条件
Python 3.8.10/unittest環境で終了制御、協調的キャンセル、部分取得、保存判断競合、ファイル単位の保存結果、確認解除、通知集約、GUI要求処理、root破棄順序を検証できること。
