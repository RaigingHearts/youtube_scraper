### 3.2 OCRによる画面認識の調査

実機GUIの確認準備として、Windows画面キャプチャ `WS002.bmp` を使い、Tesseract OCRによる画面文字認識を試した。

記録された環境・条件：

- Tesseract 4.0.0.20190314（Leptonica）
- Python 3.8.10環境でPillowを使用
- 日本語OCR（主に `-l jpn`、一部 `jpn+eng`）
- `--oem 1`
- PSM 6、7、その他の比較
- 画面全体、領域切り出し、拡大画像、グレースケール等を比較

画面全体では一部のラベルを認識できた一方、短い英数字や小さなボタン文字に誤認識・欠落があった。ウィンドウタイトルや「取得完了JSONファイルを開く」ボタンなど、個別領域の切り出しも試した。

### 3.3 JSONボタンの切り出し実験（2026-11-24）

45×27pxのJSON領域を中心に、左右の切り出し範囲や白いパディングを1～3px単位で変更し、Tesseract TSVの認識文字列・bbox・confを比較した。

結果は `JSON-`、`JSON:`、`JS0N:`、`JSON2` などに変動した。切り出し範囲や周辺画素によってOCR結果が変わることは確認できたが、confは正解率そのものではなく、この実験だけで誤認識の原因を特定したわけではない。

NEAREST／LANCZOSによる4倍画像も作成し、コミット `8202ea17140ec35113b6915f60860606b9da6496`（`test(ocr): add pirts crop`）に追加されたことが確認されている。

このOCR実験は、画面認識の特性を調べるものであり、GUI受け入れテストの実用性・費用対効果が確立したことを意味しない。

## 4. 2026-11-24の方針見直しと最終判断

テスト準備・実施・保守に必要な作業量と、個人利用を目的とする本プログラムの規模・用途を比較し、実機GUI受け入れテスト自体を必須要件とする必要があるかを再評価した。

### 結論

**実機GUI受け入れテストおよびその自動化は、本プログラムにおいて必須要件とはしない。**

OCRによるGUI表示の自動判定についても、現時点で導入する必要性は認められない。画像の準備・切り出し・OCR精度調整・テスト環境の維持に過大な作業を要する状態は、個人開発の本来の目的であるプログラムの実装・改善に対して費用対効果が釣り合わない。

### 今後の基本方針

- 構文・インポート確認、主要処理の単体テスト、外部サービスとの連携確認など、プログラムの主要機能の品質確認を優先する。
- GUIについては、必要な場合に実際の利用環境で手動確認する。
- 実機GUI受け入れテストの自動化、OCRによる画面判定、画像のピクセル単位の調整は、現時点では実施対象から外す。
- 将来、GUI変更の頻度や手動確認の負担が増し、自動化の費用対効果が明確になった場合に限り、必要な範囲で再検討する。
- 今回のOCR画像切り出し・拡大・パディング比較は、OCRの特性確認として一定の知見を得た段階で終了し、これ以上の精度調整は行わない。
