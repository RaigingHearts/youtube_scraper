# 「所感を評価する」対話ログの第三者独立監査レビュー

## 目的

「所感を評価する」コンテキストウィンドウ群の保存ログを一次資料として、Youtube Scraper開発の対話中に発生した作業・判断・進捗・未完了事項について、脇道への逸脱や話題の切り替わりによる忘却、対話上の見逃し、記録の不整合、残務探索の漏れがないかを第三者の独立した視点で確認する。

このレビューは、過去に作成されたPull Requestのコードを再レビューするものではない。過去のPRやIssueは、会話ログに記録された作業・判断の現状を照合するための参照資料としてのみ使用する。

## 参照資料

- 保存ログ：[`docs/所感を評価するコンテキストウィンドウログ/`](所感を評価するコンテキストウィンドウログ/)
- 残務処理の指針・探索マップ：[`docs/残務処理の確認.md`](残務処理の確認.md)
- 横断管理Issue：[Issue #29 - 残務処理への対応](https://github.com/RaigingHearts/youtube_scraper/issues/29)

レビュー対象は、保存されている初回コンテキストおよび「所感を評価する」(1)〜(98)の各ログと、そのログに含まれる関連画像・添付資料です。レビュー開始時点のリポジトリ最新状態を確認し、ログの追加・更新があれば実際に存在する資料を対象にしてください。ファイル名や探索マップの記載だけで本文確認済みと判断しないでください。

## レビューで確認すること

1. 各コンテキストウィンドウで行われた作業、決定、保留、未実施、失敗、次の予定を抽出する。
2. 会話の途中で話題が変わったことにより、未完了の作業や確認事項が放置・忘却されていないかを探す。
3. ユーザーが明示した要望・了承・拒否・方針と、アシスタント側の提案・実行報告・後続記録の間に不整合がないかを確認する。
4. 実施済み、未実施、未確認、意図的に対象外、完了扱いとした事項を区別する。
5. Issue #29および「残務処理の確認.md」の探索マップ・監査記録と、ログ本文の記載を照合し、欠落・重複・誤分類・過早な完了判定・古い状態の残存を指摘する。
6. 必要に応じて現行GitHubのIssue、PR、コミット、ソース、テストの状態を参照し、ログに記録された作業が現在どの状態にあるかを確認する。
7. 発見事項を既存Issue等へ対応付ける。既存Issueで管理済みのものは、単に再発見しただけで新規残務と二重計上しない。
8. 会話ログ内の事実と、レビュー者の推測・評価・提案を明確に分ける。

## レビュー上の注意

- 過去PRのコード品質、設計、実装、テストを改めてレビューすることを目的にしない。必要な場合も、残務の現状照合に必要な範囲だけ参照する。
- 過去のテスト成功・実API検証・GUI操作・ビルド等の記録は、当時の実行報告として扱う。現在再実行したと表現しない。
- ログや探索マップに記載されていない内容を推測で補完しない。
- IssueがOpenであることだけを根拠に、未着手・未解決と断定しない。逆にClosedやMergedであることだけを根拠に、会話上の残務がすべて解消したとも断定しない。
- 保存ログには機密情報・認証情報が含まれている可能性がある。値を再掲、利用、外部送信せず、必要な場合は種類・所在・影響を伏せ字で報告する。認証情報の有効性を試さない。
- レビュー中にGitHubへレビュー投稿、Approve、Request changes、コメント投稿、Issue更新、コード変更、コミット、プッシュ、マージを行わない。
- レビュー結果は、依頼元の専用コンテキストウィンドウへ報告する。PR上に結果を投稿しない。

## 独立レビュー依頼プロンプト

このPRの説明欄に記載した依頼テンプレートを使用し、レビュー対象PRとして本PRを指定する。レビュー依頼は、過去のコードPRの再レビューではなく、上記保存ログ群を対象とする遡及的な残務探索・監査であることを明示する。
