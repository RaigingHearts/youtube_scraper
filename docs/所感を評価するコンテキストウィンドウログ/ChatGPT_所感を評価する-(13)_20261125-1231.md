## 追加で修正したい点：最終ページ内の進捗総数

現在の処理では、コメントスレッドの最終ページを取得した直後に、

```python
comment_threads_completed = not bool(next_page_token)
```

として取得完了状態を `True` にしています。

一方、`total_threads_expected` と `total_replies_expected` は、その後の `for thread_index, thread in enumerate(...)` のループ内で1スレッドずつ加算されています。

この組み合わせだと、例えば最終ページに親コメントが10件ある場合、最初の親コメントの返信を取得した段階で、まだ残り9件の見込み数を加算していないのに、進捗コールバックへ「確定済みの総数」として途中の値を渡す可能性があります。

ページ処理終了時には正しい総数になりますが、途中の進捗表示が一時的に不正確になります。

### 修正方針

返信ページ取得中の進捗コールバックでは、最終ページの最後のスレッドまで処理した場合に限り総数を渡すようにします。

現在の条件：

```python
(total_threads_expected +
 total_replies_expected) if comment_threads_completed else None
```

修正する条件：

```python
(total_threads_expected +
 total_replies_expected)
if comment_threads_completed and thread_index == len(thread_items)
else None
```

最終ページの最後のスレッドより前では `None` を渡し、全スレッドの見込み数が集計された段階で確定値を渡します。最後のスレッドに返信がない場合も、ページ処理終了後のコールバックで正しい総数が通知されます。

この修正に合わせて、**最終ページに複数の親コメントがあり、途中の返信取得時には総数が未確定、最後には確定することを検証するテスト**も追加したいです。
