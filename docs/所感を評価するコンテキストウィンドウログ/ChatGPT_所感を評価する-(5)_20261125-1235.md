## 3. では、共通モジュールとプログラム本体のログは区別しないのか？

ここは区別できます。

例えば、

```python
# settings_manager.py
import logging

logger = logging.getLogger(__name__)

logger.info("設定ファイルを読み込みました。")
```

```python
# main.py
import logging

logger = logging.getLogger(__name__)

logger.info("アプリケーションを起動しました。")
```

このように、各モジュールがそれぞれ名前付きLoggerを取得すれば、ログの発生元を識別できます。

例えば出力時に、

```text
2026-11-18 08:00:00 INFO module.manager.secure_settings.settings_manager 設定ファイルを読み込みました。
2026-11-18 08:00:01 INFO __main__ アプリケーションを起動しました。
```

という具合です。

必要であれば、共通モジュール由来のログとアプリケーション本体由来のログを、出力形式やログレベル、保存先などで分けることもできます。

ただし、それはLoggingの設定側で制御する方が自然です。

## 4. 今回のIssue \#15で明確にしたいこと

| 項目 | 役割 |
|--------|--------|
| Logging | ログ記録機構そのもの |

この方針なら、共通モジュールが増えてもログ機構を増設する必要がなく、初期化順序の問題もかなり単純化できます。
