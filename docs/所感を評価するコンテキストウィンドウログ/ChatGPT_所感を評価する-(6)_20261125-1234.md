例えば、次のような呼び出しを考えてみます。


- FileHandlerのログレベル：`INFO` のまま
- ルートロガーのログレベル：`DEBUG` に変更

という不整合が発生します。

### ログのラベルによる使い分けとは別の話

例えば、次のような構成は標準 logging でも実現できます。

| ロガー名 | 用途 |
|---|---|
| `module.utility.youtube_api_client` | YouTube API関連 |
| `module.manager.secure_settings` | 設定管理関連 |
| `module.single.file_operations` | ファイル操作関連 |

さらに、それぞれのログを別ファイルに振り分けることも可能です。

ただし、それは `configure_logging()` の初期化処理とは別に、各ロガーやハンドラーのフィルタリング・出力先を設計する話になります。

### 今回の修正方針

私は、現段階では次の方針が適切だと思います。

1. 同じ設定で複数回呼び出された場合は、既存のハンドラーを再利用する。
2. 異なる設定で呼び出された場合は、既存ハンドラーの出力先とログレベルを更新する。
3. 同じハンドラーが重複登録されないようにする。
4. それぞれの設定変更が正しく反映されることをテストする。

つまり、今回の指摘はログファイルの使い分けを否定するものではありません。むしろ、将来的にログ出力の構成を変更する可能性も考慮して、初期化関数の動作を明確にしておこう、というものです。
